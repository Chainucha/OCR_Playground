# Run OCR (Side by side)

A signed-in teammate adds one or more photos, scans or PDFs (by drag and drop or the file picker), picks models, optionally adds the correct text for each page, and presses Read. Every PDF page becomes its own page, rendered to an image in the browser in the background. Pages are read one after another. For the page chosen in the page list, the results are one row of columns: the page image, its correct text, then one column per model. A model's column starts with its score (number of mistakes, accuracy, seconds) and then its text. From 768px up every column's text starts at the same height (CSS subgrid); below that the columns stack. Pressing Read closes the correct-text box, because the correct text shows as a column. With correct text, mistakes are marked word by word: `del` is what the page says, `ins` is what the model wrote instead. The page uses friendly model names from `web/src/lib/models.ts`, never engine ids.

## Sub-features

- `ocr-engine-list`: the `N models` popover lists every model. Models the server can't run are disabled with "Not set up on this server yet."
- `ocr-choose-page`: added files appear at once in `ul[aria-label="Pages"]`, each with a thumbnail, its name and a `Remove <label>` button. The first new page becomes the chosen one (`aria-current`). The Read button reads `Read with N models`, or `Read P pages with N models` when there are several.
- `ocr-pdf`: pdf.js renders each PDF page at 200 DPI in the browser, one page at a time. The PDF shows up at once under its file name. Once it opens, that entry becomes `<file>.pdf · page 1` and pages 2..N follow it. Each page says `Preparing…` with a spinning placeholder until its image is ready. The spinner stops under reduced motion.
- `ocr-pdf-failed`: a PDF that can't be opened stays in the list with `Couldn't open this PDF. It may be damaged or password-protected.` It can be removed, and Read skips it and leaves it out of the page count.
- `ocr-multi-file`: one pick or drop can add several files, and they add to the list. Other file types are refused with `We couldn't add <name>. Only photos, scans (PNG or JPG) and PDFs work.`
- `ocr-drag-drop`: files dropped on the dashed area are added, and the area turns amber while files are over it. A file dropped just outside the area doesn't open in the tab.
- `ocr-remove`: `Remove <label>` removes one page and `Remove all` removes every page, along with their results. Both work at any time, also while pages are preparing or being read. Focus moves to the next page, or to the file picker when none is left.
- `ocr-switch-page`: choosing another page in the list shows its results (`How each model did on <label>`) and its own correct text. A page read in this press of Read shows `Read` with a check in the list, and the page being read shows `Reading…`.
- `ocr-run`: pages are read in list order. Read is enabled once there is a page that hasn't failed and every model is warm. Read waits for a page that is still preparing (`Preparing page n of N…`), skips failed ones, and also reads pages added during the read, so `N` in `Reading page n of N…` can grow. With one page the button just reads `Reading…`. For each page: one column per selected model, in the picker's order. Each column's head moves from `Reading… <n> sec` (ticking from its own start) to a result or a plain-language failure. A model's time runs from sending the request to getting the result. When everything has answered, the `#results [role=status]` line ends with `One at a time, <a> sec in total.`, or `All at once, <a> sec in total (the separate times add up to <b> sec).` With no page, Read is disabled and `#read-why` says `Add a page to start.`
- `ocr-run-mode`: the `How to run` radio group sits in the toolbar as two segments, and it is locked while a read is going. `One at a time` (the default) reads in column order: later columns say `Waiting for its turn` until their model starts. `All at once` starts every model together, and each model column notes `The time may read high: other models were reading at the same time.` Either way, each server model gets its own `POST /ocr`.
- `ocr-stages`: each finished model column has a `Where the time went` disclosure, collapsed by default. Opening or closing it in one column does the same in every column. It holds a table of stages in order, without overlap, ending with `Total`. Every table starts with `Send and receive`. Server models then show `Receive page` and `Wait to start`, then their own stages, then `Score accuracy` when correct text is given. `openthai-text` reports `Open image`, `Find text lines`, `Read text` and `Assemble text`, and the private model shows the same names from its port. Models that don't report stages show one `Engine` row.
- `ocr-warmup`: when the page opens, every available model reads the practice page `web/public/warmup.png` until it has done 2 pages (`WARMUP_RUNS`). Meanwhile its line in the popover reads `Getting ready: reading a practice page…`, the Read button reads `Getting models ready…` and is disabled, and `#getting-ready` explains why. `GET /engines` reports each engine's `runs`, so a reload sends no practice pages to a warm server model. A result read during warm-up notes `The time may read high: the model was still warming up.`
- `ocr-cer`: with correct text, each model's head shows `N mistakes` (or `No mistakes`) large, then `xx.x% accurate, took x.x sec`. `Fewest mistakes` appears only when one model is strictly ahead.
- `ocr-diff`: `Highlight mistakes` switch, on by default, marks wrong words. Thai words come from `Intl.Segmenter`, so a wrong tone mark is shown inside its word.
- `ocr-api-down`: a notice says only OpenThai2.1-OCR-Text in your browser is available. That model stays runnable.
- `ocr-browser-engine`: OpenThai2.1-OCR-Text · in your browser runs in a Web Worker and sends nothing to the engine API.

## How to get to it (user POV)

- Sign in. Side by side is the only page.
- Drop photos, scans or PDFs on the dashed area, or click it to choose files. Open `Add the correct text` for a page if you have it, then press Read. Choose a page in the list to see its results.

## Driving it with agent-browser

Preconditions:

- Signed in as in `sign-in.md` (`main` exists).
- `verify.py doctor` shows `openthai-text=ready`.

- **Wait for the model list and warm-up.** The list loads after sign-in, and warm-up starts at once. Until both finish, the buttons read `1 model` or `Getting models ready…`. `agent-browser wait --fn "[...document.querySelectorAll('button')].some(b=>b.textContent.trim()==='Read with 2 models')" --timeout 60000`. To watch the gate itself, attach a `MutationObserver` right after `wait main` that logs the Read button's text and `disabled` state. On 2026-11-25 it went `Getting models ready… [disabled]` then `Read with 2 models [disabled]` (no page chosen yet). Before any upload, `.verify/logs/engine.log` held 2 `POST /ocr` lines and `GET /engines` showed `openthai-text` with `runs` 2.
- **Choose page.** `agent-browser upload 'input[type=file]' "$PWD/data/samples/synthetic-invoice-001.png"` (forward slashes). The page list shows `synthetic-invoice-001.png`, chosen, and the button reads `Read with 2 models`.
- **Several files and a PDF.** Make a 2-page test PDF outside git: `python -m uv run --with pillow python -c "from PIL import Image; i=Image.open('data/samples/synthetic-invoice-001.png').convert('RGB'); i.save('<scratch>/two-page.pdf','PDF',save_all=True,append_images=[i])"`. Upload it together with the PNG (`agent-browser upload` takes several paths), then `agent-browser wait --fn "document.querySelectorAll('ul[aria-label=Pages] img').length===3"`. Read the labels with `[...document.querySelectorAll('ul[aria-label=Pages] [data-page]')].map(b=>b.textContent)`. On 2026-11-25: `synthetic-invoice-001.png`, `two-page.pdf · page 1`, `two-page.pdf · page 2`, with the PNG chosen and the button at `Read 3 pages with 2 models`.
- **Model list.** `agent-browser find role button click --name "2 models"`, then `agent-browser snapshot -i`. Checkboxes `OpenThai2.1-OCR-Text · in your browser …` and `OpenThai2.1-OCR-Text …` are checked. `OpenThai2.1-OCR-Markdown` and `Typhoon OCR` are disabled with "Not set up on this server yet." Press Escape to close.
- **Correct text.** `agent-browser find role button click --name "Add the correct text"`, then `agent-browser fill '#correct-text-input' "$(cat data/samples/synthetic-invoice-001.gt.txt)"`. The toggle now reads `Correct text added`.
- **Read.** `agent-browser find role button click --name "Read with 2 models"`, then `agent-browser wait --fn "document.querySelector('#results [role=status]')?.textContent.includes('in total')" --timeout 90000`.
- **Result.** `agent-browser eval "JSON.stringify({status: document.querySelector('#results [role=status]').textContent, marks: [...document.querySelectorAll('#results del, #results ins')].map(m=>m.tagName+':'+m.textContent)})"`. On 2026-11-25 both models scored `2 mistakes` at `99.0% accurate`, there was no `Fewest mistakes` badge (a tie), and the status was `2 finished. One at a time, 2.2 sec in total.`. The marks were `DEL:page says ที่` / `INS:model wrote ที` and `DEL:page says มูลค่าเพิ่ม` / `INS:model wrote มูลค่าเพิม` in each column. The legend above the columns holds one more `del`/`ins` pair as an example. A large change means an engine, the metric or the diff changed.
- **One at a time.** Before Read, attach a `MutationObserver` that logs each model column head's `p` texts. `OpenThai2.1-OCR-Text` reads `Waiting for its turn` until `OpenThai2.1-OCR-Text · in your browser` has a result. No column carries a may-read-high note.
- **Where the time went.** `agent-browser eval "document.querySelectorAll('#results details summary').forEach(s=>s.click()); JSON.stringify([...document.querySelectorAll('#results table')].map(t=>[...t.rows].map(r=>[...r.cells].map(c=>c.textContent).join(' / '))))"`. On 2026-11-25 the private model took 0.91 sec (Find text lines 54%, Read text 39%), and `OpenThai2.1-OCR-Text` took 1.33 sec (Find text lines 55%, Read text 42%). The rows add up to `Total` within rounding.
- **All at once.** `agent-browser find role radio click --name "All at once"` in the toolbar, then Read. Both model columns read `Reading…` together, the private one finishes first, and both carry the may-read-high note. On 2026-11-25 the status was `2 finished. All at once, 1.5 sec in total (the separate times add up to 2.5 sec).`.
- **Read every page.** With those 3 pages and correct text on the PNG only, log the Read button's text with a `MutationObserver`, click `Read 3 pages with 2 models`, and wait until it reads that again. On 2026-11-25 it went `Reading page 1 of 3…`, `2 of 3…`, `3 of 3…`, then back. Every list entry gained `Read`. The PNG's results were `How each model did on synthetic-invoice-001.png`, both models at 99.0% with 2 mistakes, and the text columns were `The page`, `The correct text`, then one per model.
- **Switch page.** Click the third `[data-page]` button. The heading becomes `How each model did on two-page.pdf · page 2`, each model's head reads `x.x sec` and `Add the correct text to count mistakes.`, each model's first line is `ใบกำกับภาษี / ใบเสร็จรับเงิน` (the PDF page was rendered and read), and the correct-text box is that page's own (empty).
- **Bad files.** Upload a `broken.pdf` holding `%PDF-1.4 junk` and a `notes.txt` together. The list gains `broken.pdf` with `Couldn't open this PDF…`, the notice reads `We couldn't add notes.txt. Only photos, scans (PNG or JPG) and PDFs work.`, and the button still counts 3 pages.
- **Remove.** `agent-browser find role button click --name "Remove broken.pdf"`. The list drops to 3 and focus lands on the neighbouring page's button. `Remove all` empties the list and focuses the file picker.
- **Drag and drop.** agent-browser has no file drag, so fire a synthetic drop: `agent-browser eval "(async()=>{const b=await (await fetch(document.querySelector('ul[aria-label=Pages] img').src)).blob(); const dt=new DataTransfer(); dt.items.add(new File([b],'dropped.png',{type:'image/png'})); document.querySelector('label:has(input[type=file])').dispatchEvent(new DragEvent('drop',{dataTransfer:dt,bubbles:true,cancelable:true})); return 'ok'})()"`. The list gains `dropped.png`.
- **Side effect.** `.verify/logs/engine.log` gains one `"POST /ocr HTTP/1.1" 200 OK` per server model per page, in either mode (3 for 3 pages with one server model).
- **Private model alone.** Untick `OpenThai2.1-OCR-Text` in the popover, then Read. One card, and `grep -c 'POST /ocr' .verify/logs/engine.log` is unchanged, which proves the image stayed in the browser.
- **Phone width.** `agent-browser set viewport 390 844`, then `agent-browser eval "document.documentElement.scrollWidth"` returns `390`, also with 4 pages in the list. Only the page list and the text-column region scroll sideways.
- **Proof.** Save `.verify/evidence/run-ocr/01-page-chosen.png`, `02-results.png`, `agent-browser snapshot > .verify/evidence/run-ocr/02-results.aria.txt`, and the `eval` output.

## Gotchas

- Use forward slashes in the upload path. A backslash path freezes the tab.
- Each press of Read replaces every page's earlier results. Adding files keeps the pages and results already there; removing a page drops its results.
- Correct text belongs to the chosen page, and it's locked while a read is going. Fill it after choosing the page. A page's results keep the correct text it had when its read began.
- Removing a page while it is being read drops its results, but its `POST /ocr` still shows in `engine.log`.
- pdf.js loads in its own Web Worker when a PDF is added, or earlier when the pointer or focus reaches the drop area. Turbopack hashes the chunk name, so look for a new `/_next/static/chunks/*.js` resource, not for `pdf` in the name. Turning a large PDF page into a PNG still blocks the main thread for 50 to 170 ms in `canvas.toBlob` (measured in PR #1).
- `ocr-api-down` needs the engine API stopped. Don't kill the engine process by name. Run `down`, then `up`, and reproduce by blocking the API URL if needed. Report it unverified if you did not reproduce it.
- Accuracy is `1 − CER`, rounded down to one decimal so a page with mistakes never shows 100%. CER ignores whitespace and Markdown or HTML markup by design; the word diff also strips markup before comparing.
- OpenThai2.1-OCR-Text · in your browser downloads its models from Hugging Face and its WASM runtime from jsDelivr on first use, so the verification browser needs internet. Its time excludes the download.
- Models that share hardware slow each other down when they read together. In this setup the private model and `OpenThai2.1-OCR-Text` both use this machine's CPU. Compare times only from `One at a time` reads.
- Without warm-up, reads 1 and 2 come out about 20 to 25% slow. That is why `WARMUP_RUNS` is 2. The practice page is the same synthetic invoice this recipe reads, so a page of a different size can still read slightly slow the first time.
- `#results [role=status]` never holds a ticking clock, because a live region that changes every 100 ms would talk over a screen reader. The ticking seconds live in each card instead.
- Read a state that a click changes, such as the locked `How to run` group, in a later `eval` than the click. On 2026-11-25 a check in the same `eval` as the Read click saw the group unlocked. A check in the next `eval` saw it locked (both radios disabled), and it unlocked when the read ended.
- Local sign-in keeps its session in localStorage, which is separate for each port. If any localhost page answers HTTP 431, the browser is sending too many old `CognitoIdentityServiceProvider.*` cookies from before this change, or from another app on localhost. Clear the cookies for localhost.
